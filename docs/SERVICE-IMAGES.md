# Service-image build and security review

The generic source build includes the application, a minimal Caddy proxy and a derived PostgreSQL 16 database image. Build all three with compose.build.yaml; the candidate references are local/private until publication approval. Chosen upstream bases/toolchains and downloaded source identities are pinned in the Dockerfiles and Go module files.

The proxy builds Caddy2.11.7 with Go1.27.3 and pinned module selections. It contains the server, compiled-component notices and a traced Debian CA trust bundle, without a shell, curl or the upstream Alpine/Brotli packages. This removes components from the runtime filesystem; it is not a scanner ignore rule. The administration API is off in the default YAML. Its root UID is retained for compatibility with existing certificate volumes, with a read-only root filesystem, no-new-privileges and only the port-binding capability. Certificate/config writes are confined to its two named volumes. Changing these defaults or enabling additional Caddy handlers requires a new review of their input paths.

The database keeps the pinned official PostgreSQL16 image, original entrypoint and data layout. Only gosu is rebuilt from verified upstream1.20 source using Go1.27.3, patched user/sys dependencies and compiled-module notices; timezone data is refreshed. The unused upstream snakeoil certificate/key are removed from the runtime filesystem. The parent layer originally contained public packaged placeholders; these were not instance credentials and must not be used for custom database TLS. No PostgreSQL port is published by the default YAML. The entrypoint still initializes permissions and drops to the PostgreSQL user; the verifier tests that identity transition without starting a database.

The application builds Psycopg-C, Pillow and CFFI from checksum-verified source against system libraries. Pillow retains the portal's supported JPEG/PNG/WebP formats and excludes optional font, TIFF/JPEG2000/AVIF and screenshot features that its upload forms do not accept. No separate Pillow library bundle remains. CFFI links the system libffi. The verifier performs real format roundtrips, checks dynamic linkage and retained source hashes, and rejects build tools or bundled-driver libraries in runtime. This does not claim the installed system/native libraries are free of advisories.

## Evidence and residual findings

tools/verify_services.py checks exact labels, compiled-component notice hashes, source identities, the CA trust-bundle hash, minimal proxy contents, absence of instance certificate data and the database helper's non-root target identity. It exports only generic images and never mounts business data. tools/verify_image.py checks the application separately. Runtime vulnerability reports, upstream source-version decisions and exact image identities belong in the release evidence packet alongside these checks.

Package-level Go findings can mention code absent from the linked binary. The OpenPGP warning requires checking the exact import graph and binary package/symbol evidence; a module version alone is insufficient. Retain the raw warning and the scoped disposition. Conversely, a linked package is not automatically a remotely exploitable feature: legacy JOSE operations used by optional PKI/provisioning paths require a separate input-path assessment against the actual Caddyfile. No general suppression is provided. The default proxy exposes reverse_proxy, has its admin API off and configures no CA-server handler.

Debian source-package matches likewise need per-component assessment. MiniZip's source-package status does not automatically apply to a zlib binary without MiniZip; production uses PostgreSQL, while local-development SQLite is a separate boundary. XML/LDAP, interactive terminal tools and privileged utilities require their own configuration and reachability evidence. Do not relabel all unfixed vendor issues as fixed or describe these maintainer checks as an independent assessment.

Publication still requires the recorded security/distribution dispositions and independent review. These generic images are not a deployment plan for an existing private installation. Preserve its assets, original keys and migration chain, rehearse against a restored copy and use a separate promotion window.
